Documentation

How AstroErg works, what it costs, how quotes are estimated, and what's still on the launchpad.

Honest status. AstroErg v1 is a quote terminal: it computes indicative swap quotes from public market data entirely in your browser. It does not create, sign, or submit transactions, hold custody of anything, or move any funds. On-chain settlement is Phase 2. Nothing in this project has been audited — and there is no formal audit industry in the Ergo ecosystem, so we will never claim otherwise.

How it works

AstroErg is a static site (no servers, no build step). When you open it, the app tries to fetch the public https://api.spectrum.fi/v1/price-tracking/markets endpoint — 393 markets at last check, no API key — and otherwise falls back to a baked snapshot in data/markets.json (pulled at build time with scripts/refresh-data.sh). The header badge tells you which one you're seeing, with the snapshot timestamp.

Why the snapshot at all? Neither api.spectrum.fi nor api.ergoplatform.com sends Access-Control-Allow-Origin headers, so browsers refuse direct fetch() calls (CORS). The snapshot is the honest workaround: same data, pulled minutes before deploy, visibly timestamped.

Quotes run the classic constant-product AMM math (x·y=k) in integer arithmetic (BigInt raw units — ERG has 9 decimals, i.e. nanoErg), with the 0.5% Spectrum-style pool fee kept in reserves. Token→token pairs route through ERG in two legs and the UI says so.

Reserve-estimation methodology

Spectrum's price-tracking API publishes lastPrice and per-side volumes per market — it does not publish pool reserves. Since a quote engine needs reserves, AstroErg estimates them: 

1. Spot price p = lastPrice
     (verified 2026-09-28: human units of QUOTE per human unit of BASE,
      e.g. ERG/SigUSD ≈ 0.305 SigUSD per ERG while ERG traded ≈ $0.32)
2. Reported volume V (quote-denominated) = max(baseVol × p, quoteVol)
     — the API does not document the volume window; we label it "reported"
3. Assumed depth D = 10 × V            ← heuristic, the key assumption
4. Reserves: R_quote = D / 2,  R_base = R_quote / p
     (50/50 by value at the spot price, stored as raw integer units)

The 10× multiplier is a guess: real pools are typically a small multiple of daily volume deep, but we cannot observe reserves, so price-impact figures scale with this guess. Every reserve figure in the UI carries an estimated label, and the quote panel says "depth: estimated". Re-pull snapshots any time with scripts/refresh-data.sh.

Fee structure

Protocol fee — 0.25% of swap input

Every quote shows the 0.25% protocol fee as a line item. It is not collected in v1 (there is no settlement to take it from) — it goes live with Phase 2 settlement, paid to:

Pool fee — 0.5%, accrues to LPs

Spectrum-style pools keep a 0.5% fee inside reserves on every swap, which accrues to liquidity providers as their share of the pool grows. AstroErg's quote engine applies this fee exactly that way — it reduces your output and stays in the (estimated) reserves.

Wallet connection

The Connect Nautilus button uses the EIP-12 dApp connector (window.ergoConnector.nautilus) to request your change address and ERG balance — read-only, display-only. It is implemented from public docs and has not been tested against a live wallet. If Nautilus isn't installed, or the connection fails, the app degrades gracefully and every quote feature keeps working. v1 never asks for a signature and never builds a transaction.

Roadmap

✅ Phase 1 — Quote terminal (this site)

Static front-end, public market data with snapshot fallback, x·y=k quote engine with honest reserve estimates, token directory, docs. No contracts, no custody, no fake trades.

🚧 Phase 2 — On-chain settlement

Fork the CC0-licensed Spectrum Finance contracts (spectrum-finance/ergo-dex), shake them down on testnet, put them through community review, then launch on mainnet with capped liquidity. Only then do the swap-settle and add/remove-liquidity buttons light up — and the 0.25% protocol fee starts flowing to the recipient above.

🔭 Phase 3 — Beyond

Limit orders, deeper routing across all pairs, and whatever the community asks for — after Phase 2 proves itself.

Risks & honest caveats

  • Unaudited code. Nothing here — front-end or future contracts — is audited. There is no formal audit industry in Ergo; we rely on open code + community review and will say so, always.
  • MEV / front-running. Ergo has public mempools; visible swap intents can be front-run by bots. Design mitigations (slippage limits, private relays) are Phase 2 work.
  • Pool-box contention. Each AMM pool is a single UTXO; concurrent swaps contend for it and some transactions will need retries. Expect this UX wrinkle in Phase 2.
  • Executor-order dependency. Permissionless off-chain executors decide transaction ordering for order-book style settlement; understand the trust model before using it.
  • Estimated depth. v1 quotes use estimated reserves (see methodology). Real execution prices will differ — sometimes meaningfully on thin pairs.
  • Token lookalikes. Anyone can mint a token with any ticker on Ergo. Verify 64-hex token IDs; AstroErg links every token to its explorer page.

Not financial advice. Software is provided as-is; verify everything on the explorer before trusting it.
